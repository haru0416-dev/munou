## 1. 目的と思想

LLMを使わず、理解せずに会話が成立する対話プログラムを現代の道具立てで設計し直す。目標は賢さではなく、次の四つの性質。

1. **説明可能** — すべての応答について「なぜこれが出たか」を生成チェーンと選択スコアで完全に追跡できる
2. **育てられる** — 語彙・遷移・記憶がユーザー可視のデータ構造であり、会話ログから育つ過程が観察できる
3. **閉じている** — 外部知識を持たない。知っていることはすべて自分の会話ログ由来
4. **ズレる** — 文脈からの適度な逸脱を欠陥でなく仕様として設計する

副目的として、トークナイザー・n-gramストア・サンプリングの各層を数理とデータ構造の遊び場にする。個人ログ規模(〜数百万トークン)では速度は本来問題にならないため、高速化は必要性でなく楽しみとして行うことを明記しておく。

## 2. 制約

- LLM(生成用言語モデル)は使わない
- embedding は**選択**にのみ使う。生成には使わない
- ミニモデルは**分類器**としてのみ許可(対話行為・感情極性など)
- 学習データは自分の会話ログのみ。事前学習済み生成モデル・外部コーパスは禁止
  - 例外: embedding モデルと形態素辞書は既製を許可(生成に関与しないため)

### 2.1 決定済みの前提

- 実装スタック: **Rust**
- インターフェース: 当面 **CLI のみ**。**観察窓が本線**（ゲージは既存の発話・吸収・語彙・帯域・暗記・ズレ）。エンジンはインターフェース非依存の crate。CLI はその最初の面。**伺か SHIORI / Misskey / 常駐アダプタは後段（劣後）**
- 参照実装(Vibrato / Vaporetto 等)は探索の下限であり、設計空間を縛らない。各コンポーネントはゼロから設計する案を常に比較対象に含める

### 2.2 非機能要件(厳しめに設定)

速度・省メモリは必要性からでなく規律として課す。満たせない場合は設計を疑う。

| 項目 | 要件 |
|---|---|
| 応答レイテンシ | 入力→出力 p99 ≤ 30ms(embed 推論込み)。embed を除くエンジン部は p99 ≤ 2ms |
| トークナイズ速度 | ≥ 50MB/s(シングルスレッド、実測プレーンテキスト) |
| インデックス再構築 | 10^7 トークンの SA 全再構築 ≤ 2s |
| 常駐メモリ | コーパス 10^7 トークン時に ≤ 256MB |
| 起動 | コールドスタート ≤ 100ms(インデックスは mmap で遅延ロード) |
| 再現性 | 同一ログ+同一シードで応答列が完全一致(決定的)。ズレ注入も擬似乱数で再現可能 |
| 依存 | 実行時の外部プロセス・外部サービス依存なし。単一バイナリで動く |
| 耐障害 | 会話ログは append-only。プロセス強制終了でログを失わない(インデックスは再構築で復元可能) |
| 割り当て規律 | 応答ホットパスでのヒープ確保ゼロを目標(アリーナ/事前確保) |

## 3. 全体アーキテクチャ

生成と選択の分業が中核。**複数の手段が候補を出し、選択器が一本を選ぶ**。v0.1 はトリガー照合が当たるとマルコフを止める XOR で、空コーパスではユーザー文をバックオフに使っていた。それはおうむ返しを設計に埋め込んでいた。最終形はハイブリッドの候補プールである。

```
入力発話
   │
   ▼
[トークナイザー] ── 形態素列 → 文節チャンク列
   │
   ├─→ [対話行為分類器] 質問/相槌/呼びかけ… (任意・後段)
   │
   ▼
[話題トラッカー] 直近k発話の embedding 移動平均 = 話題ベクトル t
   │
   ├─→ [トリガー]     辞書応答
   ├─→ [検索]         過去の自分の発話（ログ由来）
   ├─→ [マルコフ]     可変長 n-gram の組み換え
   └─→ [エコー]       入力の再掲（明示。黙ってのフォールバックではない）
          │
          ▼
     [候補プール]
          │
          ▼
[選択器] 話題余弦 ± ソース事前 − 連続部分列 − 帯域ヒンジ
   │      ★ズレ注入: 確率 p で 2 位以下を Boltzmann サンプル
   ▼
[記憶] 発話をログへ追記。確率 p_learn でコーパスへ吸収（トークナイザ・SA・検索）
   │
   ▼
[観察窓] 吸収 / 語彙 / 帯域 / 暗記 / ズレ。会話より「育つ様子」が製品
   │
   ▼
出力
```

`--mix exclusive` は v0.1 の XOR を残す。既定は `--mix pool`。

## 4. コンポーネント設計

### 4.1 トークナイザー(自作対象)

既存二方式に限定せず、ゼロから設計する第三案を対等に置く。比較軸だけ固定する。

| 軸 | ラティス+Viterbi (MeCab系) | 点予測 (KyTea系) | ゼロ設計(教師なし/タスク駆動) |
|---|---|---|---|
| 構造 | 辞書引き+最小コスト経路 | 各文字境界を分類器で判定 | 統計量から境界を直接導出 |
| 速度の主戦場 | トライ/FST、接続表のキャッシュ効率 | 特徴量抽出、線形分類器の内積 | 統計量の前計算とルックアップ |
| 隠れコスト | 辞書メンテが重い | 学習データ作りが要る | 品詞が出ない。分割品質の保証がない |
| 品詞 | 自然に取れる | 追加タスクになる | 別途設計するか、不要にする |
| 参照点 | Vibrato (Rust) | Vaporetto (Rust) | 分岐エントロピー法、accessor variety 等 |

ゼロ設計の核になるのは二つの問い。

- **教師なし境界検出**: 文字 n-gram の**双方向**分岐エントロピー（境界の左右で次/前の文字の多様性が跳ねる位置を境界とみなす）は辞書も教師データも要らず、自分のログだけで完結する。制約2(閉じている)と最も整合的
- **タスク駆動分割**: そもそも言語学的に正しい分割は目的ではない。マルコフの単位として最適な分割 — 生成品質(§6 の指標)を直接最大化する分割 — を探索対象にできる。トークナイザーを独立部品でなく、生成器と結合した最適化問題として扱う道

文節単位マルコフをやるには品詞相当の情報が要る。ゼロ設計を選ぶ場合、「文節」に固執せず統計的チャンクで代替できるかも含めて実験する。

出力は二層: 形態素列(学習・分類用)と文節チャンク列(マルコフの単位)。全トークンは interning して u32 ID に落とす。

### 4.2 コーパスストア

会話ログ全体を u32 ID の一本の配列として保持し、その上に接尾辞配列(SA-IS で O(n) 構築)を張る。

- 可変長 n-gram: 固定次数の HashMap を持たず、任意長の文脈を SA 上の二分探索で引く。次数固定による丸暗記問題が構造ごと消える
- 更新: incremental SA は難しいので世代制にする。新規発話は小さな HashMap バッファに置き、閾値超過時(または夜間)に本体へマージして SA を全再構築。数百万トークンなら再構築は一瞬
- 生成時は本体 SA とバッファの二段引き

### 4.3 マルコフ生成器

- 単位: 文節チャンク。文法的破綻を抑えつつ意味のズレを残す
- 次数: 可変長。接尾辞次数 1..n を短い順に補間する。`f_min` は説明用の「効いている次数」であり、確率は全次数を混ぜる（長い一致だけ見て unigram に飛ばさない）
- 平滑化: 既定は Witten-Bell（`λ = N/(N+T)`）。`--smoothing kn` で modified Kneser-Ney（Chen-Goodman の D1/D2/D3+）。いずれも下位分布への補間。KenLM 本体・ARPA は使わない
- サンプリング: 分布ごとに alias 法を前計算し O(1) 抽選。温度パラメータで分布を変形
- 停止: 文末トークンの明示 + 最大長ガード
- 疎な文脈だけ skip-gram（直前を一つ飛ばした次数）と recency cache を混ぜる

### 4.4 選択器

- 候補 N 本を embedding し、話題ベクトル t との内積でランク。**帯域ヒンジ**で [lo, hi] の外を減点する（余弦最大化は §6 の帯域目標と衝突するため）
- 丸暗記減点は入力との **token 連続部分列**（部分列 LCS は組み換えまで減点してしまう）
- 検索提案は MMR（類似 − 冗長）でクローンを減らす
- この規模では ANN(HNSW)は不要。SIMD の総当たり内積で足りる。埋め込みは i8 量子化を検討
- **ズレ注入**: 確率 p_slip で 2 位以下を Boltzmann（`τ_slip`）サンプル。トリガー閾値も意図的に緩く保つ。ズレはパラメータであって欠陥ではない

### 4.5 分類器(任意・後段)

対話行為(質問/相槌/挨拶/呼びかけ)と感情極性の小分類器。応答プールの切り替えに使う。線形モデルか数十MB以下の蒸留モデル。v1 では省略可。

### 4.6 記憶

- 短期: 話題ベクトル(直近 k 発話の移動平均)
- 長期: 発話ログ本体 + embedding index。「前に言ったこと」の検索に使う
- 固有記憶(名前・好み等の key-value)は v2 以降の検討事項

## 6. 評価 — 未解決の中核問題

perplexity 最小化を目的関数にするとログ再現に向かい、無脳らしさが死ぬ。面白さの定式化が本プロジェクト最大の open problem。候補となる代理指標:

- 文脈類似度の**帯域**目標: 高すぎず低すぎない範囲 [a, b] に収まった応答の率
- 新規性: 生成文とログ既存文の**最長連続一致**長(丸暗記検出)
- 破綻率: 文法破綻の人手アノテーション(小規模でよい)

当面は自動指標+自分の主観ログの併用とし、目的関数の設計自体を実験対象として扱う。

## 8. 実装順序

1. トークナイザー(選定方式のミニマム版) + interning
2. コーパスストア(ログ配列 + SA + 世代バッファ)
3. マルコフ生成器(素朴バックオフ + alias 法)— ここで一度 CLI で会話可能に
4. 選択器(embed リランク + ズレ注入)
5. 話題トラッカー・トリガー辞書
6. 候補プール（トリガー + 検索 + マルコフ + エコー）と反おうむ返しスコア
7. 観察窓（既存指標のゲージ）。アダプタ（伺か / Misskey / 常駐）は劣後
8. Kneser-Ney 差し替え、量子化、SIMD 化(楽しみ枠)
9. 分類器・長期記憶・対話行為別プール(v2)

## v0.1 で固定した決定

未決だった項目を、動く実装のために仮置きする。名前もトークナイザーも後から差し替えられるように切ってある。

| 項目 | 決定 | 理由 |
|---|---|---|
| クレート名 | `munou` / 表示名 人工無脳君 | プレースホルダ。ラテン語スタイルの改名は容易 |
| 言語 / 版 | Rust 2021, MSRV 1.83 | この環境の rustc に合わせた。edition 2024 は後で |
| インターフェース | `munou-engine` + `munou` CLI。観察窓（`munou observe` / `/observe`）が本線 | 設計 2.1。伺か / Misskey / 常駐は後段 |
| トークナイザー | ゼロ設計: 双方向分岐エントロピー。弱いモデル時は CJK を文字単位 | 「閉じている」と最も整合。文節の代わりに統計チャンク |
| embedding | 閉じた特徴ハッシュ (char n-gram、次数に比例した重み → dim 256)。`Embedder` trait | 単グラムがベクトルを占めないようにした |
| 平滑化 | `Smoothing` trait。既定は Witten-Bell。`--smoothing kn` は modified KN（コーパスの bigram 頻度から D1/D2/D3+）。次数は短い順に補間。KN 経路は PPM-C 除外 | 長い n-gram だけ見て unigram に飛ばすと中間文脈が死ぬ。KenLM は入れない |
| 再現性 | `ChaCha8Rng` + シード。壁時計はログの `t` にしか使わない | |
| 耐障害 | `munou-data/log.jsonl` を append + `sync_data`。インデックスはログから再構築 | mmap コールドスタートは未実装 |
| 評価 | 帯域ヒット率 + 既存発話との連続部分列。`/eval`。帯域は選択器のヒンジにも使う | 面白さの定式化は open のまま。ヒンジは区間制約の凸緩和 |
| 候補 | 既定は `pool`。トリガー・検索・マルコフ・エコーが同時に提案し、選択器が選ぶ | XOR は `--mix exclusive`。対話行為プールはまだ |
| 学習 | 既定 `p_learn=0.35`。会話ログは append-only、コーパス（SA / 検索 / トークナイザ統計）へは乱数で吸収。フラグは JSONL の `learned` | 毎回覚えるとおうむ返しに寄る。シードログはフィールド省略＝吸収済み |
| 観察 | `Observe`。stage は発話・吸収・token 数。ゲージは吸収率・語彙・帯域ヒット・(1−rote)・slip。ボット行に `path` / `novelty_lcs` / `n_tok` を残し再開後も経路と eval が復元。記憶は作業（話題窓）/ 挿話（ログ）/ 母数（SA・語彙）の三層表示 | タマゴッチ型の感情モデルは足さない。HTML はローカルダンプのみ（サーバなし） |
| 逆輸入 | LLM スタックの語彙だけ借りる。nucleus / 経路ゲート / 記憶層 / `/good` `/bad` 事前。生成は接尾辞配列のまま | OpenAI・HF hub・事前学習重み・MCP を製品にしない |
| 規模 | `munou fabricate` / `munou scale` がシードと同じ雑談型を組み合わせて発話を増やす。検索は直近 `n_retrieve_scan=1024`（0 で全件） | Wikipedia 等の外部コーパスは使わない。`data/seed.jsonl` の 50 件は変えない |

実装順序 1–7 と、KN の差し替え口までが入っている。mmap / i8 量子化 / SIMD / 対話行為分類器 / 固有記憶はまだない。伺か SHIORI / Misskey / 常駐は意図的に後回し。

v0.1 を設計書に突き合わせた記録は [`docs/verify.md`](verify.md)。再現は `munou verify`。

## v0.1.5 LLM エコシステムの逆輸入

LLM は使わない。エコシステム（API、Hub、重み、チャット製品）も直接は使わない。借りるのは**概念の形**だけ。閉じたデータ構造に写す。

| LLM 側の語 | munou の写し | 使っていないもの |
|---|---|---|
| temperature / top-p / logprobs | `τ_gen`・`p_nucleus`（既定 1＝無効）・`k_top`・`GenStep.p`/`logp` | モデルロジット、OpenAI logprobs |
| KV cache | `generate_one` 内の `next_counts` メモ | Transformer のキー値キャッシュ |
| MoE / RAG vs weights | `route::plan` が検索枠とマルコフ枠を Cosine とストア占有から配分 | ニューラルルータ、外部検索 API |
| MemGPT 記憶層 | 観察窓: 作業＝話題窓、挿話＝JSONL、母数＝SA/語彙 | ベクトル DB、クラウドメモリ |
| RLHF / DPO | `/good` `/bad` → `path_prior[4]` を選択スコアへ加算。JSONL `role=meta` | 報酬モデル、選好データセット |
| tool / MoE trace | `Trace.route` を `/why` に出す | function calling、外部ツール |

既定の `p_nucleus=1` は次数補間の裾を落とさないため。`--top-p 0.9` で nucleus を足せる。好み行はコーパスに入らない。シード 50 発話は変わらない。

## v0.1.6 学習ログを膨大にする

外部コーパスは使わない。増やすのはシードと同じ生活ログの型（散歩・コーヒー・猫・仕事・ゲーム・挨拶）だけ。`unique_frac=0` なら語彙はほぼ増えず、発話数と SA 長だけが伸びる。それが「同じ人と長く話した」に近い。

検索は全 bot 発話の埋め込みを毎ターン取ると O(N) になるので、既定は直近 1024 件だけ見る。`--retrieve-scan 0` で全件に戻せる。

## v0.1.7 古典 LM の逆輸入

KenLM も word2vec も PPM 圧縮器も入れない。借りるのは次数と割引の形だけ。生成器は接尾辞配列のまま。

| 古典 LM 側の語 | munou の写し | 使っていないもの |
|---|---|---|
| Modified Kneser-Ney | `--smoothing kn`。bigram の count-of-counts から Chen-Goodman の D1/D2/D3+。λ = (n1·D1+n2·D2+n3+·D3)/N | SRILM、ARPA ファイル |
| KenLM | SA がトライ相当。`NextMemo` が probing 相当。割引は上の MKN | `kenlm` クレート、lmplz、mmap バイナリ |
| 可変長 n-gram / PPM / context tree | SA が任意長文脈。短い順に補間。KN 経路は PPM-C 除外（長い次数で見た型を下位から除く）。`--ppm` で Witten-Bell にも除外 | PPM* 圧縮、明示的な context-tree ノード |
| Skip-gram cache LM | 疎な文脈だけ、直前を一つ飛ばした次数と直近 12 トークンの unigram cache を混ぜる（`lambda_skip` / `lambda_cache`） | word2vec skip-gram、ニューラル cache |

既定の平滑化は Witten-Bell。最長一致が `f_min` 以上なら skip/cache は混ぜない（丸暗記テストを壊さない）。`kn_discount=0` は割引オフ（soak のアブレーション）。シード 50 発話は変わらない。
